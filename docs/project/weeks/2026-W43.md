## Decision for Tue 20: how to persist the freshness store

| Option | What | For | Against |
|---|---|---|---|
| **A. Two-slot record in work flash** *(recommended)* | Two sectors, each holding `{seq, epoch/floor values, CRC}`. Commit = write the other slot, then it's valid. Load = the newest valid slot. | About a day of work; easy to reason about power loss (the old slot stays valid until the new one is written); a direct fit for the `secoc_freshness_store` port | Not general-purpose; one erase per commit (per boot, so wear is negligible) |
| B. Full `eeprom_emu` | The parked general EEPROM-emulation module | Reusable; the roadmap's original plan | A multi-week module, so it won't fit M5B; it's parked in `plan.md` for that reason |
| C. Defer to M6 | Mark REQ-006/007/008 as "host-only, deferred" | No work | Breaks the published M5a promise ("M6 moves it to flash") for longer, and the reset-then-replay demo stays broken |

**G2 + G3 — Node B reset: resync, then the old frame is refused, ~45 min (the main result)**
- [ ] 1. Link healthy. Note A's epoch **E** from `0x121` in can_sniff.
- [ ] 2. `secoc_attack replay --save docs/bench/2026-10-24/old_0x121.json`: a genuine frame at epoch E.
- [ ] 3. **Reset Node B** (reset button). Expected, in order:
      - B's boot `0x2F0` carries floor **E+1** (FRESH_SYNC payload, u16 LE).
      - B logs a few `REJECT_FRESHNESS` on `0x121`, because A is still at epoch E. Note how many.
      - A logs `SECOC_RESYNC`, and `0x121` moves to epoch **E+1**.
      - B logs `ACCEPT` again, and the courtesy light works again.
      **This is Stage 7, happening without the M5 hack (G3).**
- [ ] 4. `secoc_attack replay --load …/old_0x121.json`: **`REJECT_FRESHNESS`, no actuation (G2).**

      results side by side in the write-up.
- [ ] 5. Repeat steps 1–4 once more. The floor goes up again and the old frame is still refused.

- [ ] Record A's and B's epochs (from `0x121` / `0x200`), then **pull USB power on both** (a real
